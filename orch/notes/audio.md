## S-1010 follow-up — multichannel and synced lyrics (branch story/fix-audio)
- Native `convert.c`: the source is opened with its own channels (`nag_source_channel_ids` in source.c gives AV_CHAN_* per channel); `plan_channels` (pure, role based: L R C LFE SL SR BL BR BC FLC FRC) picks the output layout and a gain matrix (`ChannelPlan`, applied by `mix()` in doubles before the resampler). `NagConvertOptions.channels` (0 source, `NAG_CONVERT_STEREO` 2); MP3 is always <= stereo. Opus: tables in Vorbis order, `opus_multistream_surround_encoder_create` (family 1, header 21+N bytes with streams/coupled/mapping). AAC: only the encoder's non-PCE layouts (1,2,3.0,4.0,5.0,5.1,7.1); 7.1's ASC channel config is patched 7 -> 12 (FFmpeg writes config-12 element order under 7). A layout the codec lacks goes into the next larger one (silent slots); BC folds into free surround slots at -3 dB; no fit -> BS.775 stereo (centre/surround -3 dB, BC -6 dB, no LFE, scaled so the louder side cannot exceed 1). >8 channels or unknown roles (heights) -> FFmpeg's own 2-channel mix. Bit rate asked is a stereo pair's: `scaled_bitrate` (+0.6 per extra full-range channel share, LFE 0.15). Host test: scratchpad `agents/story-fix-audio/chtest.py` (tone per channel; not committed).
- Tags (`tags.cpp`): `nag_tags_copy` carries SYLT (all ms frames) to MP3, or makes SYLT from LRC text in the source's lyrics (`parseLrc`: multi stamps, [offset:], word stamps dropped); Opus/M4A get `LYRICS` = LRC made from the source's first SYLT (`lrcFrom`). `plainLyrics`, `syncedSets` helpers shared with `nag_tags_read_lyrics`.
- Kotlin: `ConvertSettings.stereo`, `NativeAudio.convert(..., rate, channels, from, to, ...)`, UI `ConvertChannels` (Source/Stereo, pref `nagmedar_convert_channels`, job JSON `channels`; jobs written before default to Stereo), "Kanallar" row in ConvertSurface (disabled with Stereo for MP3). CLI `--stereo`; test-audio.sh's 5.1 case uses it.
- FGS timeout (Android 15+): worker unchanged and still correct (stopReason FOREGROUND_SERVICE_TIMEOUT -> paused notification, Result.retry, job reparsed from ConvertStore incl. channels). The loudness re-scan of a multichannel output is not interruptible (runs after the last progress poll); a stop during it is seen at the next 0.98 poll.
